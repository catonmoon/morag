# Миграция: короткие коды документов для агента

Инструкция для оператора действующего инстанса. Переводит корпус на короткие идентификаторы
(`D7QK2MV` вместо `local:corp:a/b/c/doc.md`), которые агент видит в выдаче инструментов и передаёт
в их аргументах. Решение и замеры — ADR-0025.

**Переиндексации не требуется.** На корпусе в тысячи документов миграция занимает секунды и не
пересчитывает ни одного эмбеддинга.

## Что меняется и что нет

| | |
|---|---|
| **Меняется** | что печатается агенту: выдача `search` и `get_doc`, `find_section`, Карта знаний, колонка каталога. Аргументы инструментов теперь принимают и код, и прежний `doc_id`. |
| **Не меняется** | `doc_id` как ключ: адрес точки в Qdrant (`uuid5(doc_id)`), каскадное удаление, обнаружение сирот, `parent_doc_ids`, `cluster_membership`, `section_id`, поле `source` в citation-событиях, транспорт live-fetch, конфиги, консоль. |

Отсюда и дешевизна: добавляется **одно поле `short_id`** в payload документов. Векторы, чанки и
связи не трогаются вовсе.

⚠️ **Инстанс без миграции продолжает работать.** Код выводится из `doc_id` чистой функцией, поэтому
печатать его можно и без поля; поле нужно для обратного разворота «код → документ» и для того,
чтобы разрешать редкие коллизии записью. Смешанное состояние (часть документов с полем, часть без)
тоже рабочее. То есть миграцию можно делать когда удобно и не одномоментно.

## 0. Предпроверки

```bash
# сколько документов и есть ли уже поле
curl -s localhost:6333/collections/<docs> | jq '.result.points_count, .result.payload_schema|keys'
python -m cli.main backfill-short-ids --config <config.yml> --dry-run
```

Сухой прогон печатает, сколько документов получат код, сколько уже имеют и сколько кодов пришлось
удлинить из-за совпадения. Ничего не записывает.

## 1. Снимок

Автоснапшотов у Qdrant нет, а цена ошибки — корпус:

```bash
curl -s -X POST localhost:6333/collections/<docs>/snapshots | jq '.result.name, .result.size'
```

Миграция только ДОБАВЛЯЕТ поле и не может удалить данные, но снимок стоит секунд.

## 2. Прогон

```bash
python -m cli.main backfill-short-ids --config <config.yml>
```

- Идемпотентна: документ с кодом пропускается, повторный запуск — пустой прогон.
- Прервалась (сеть, Ctrl-C) — просто запустить снова, недоделанное доназначится.
- Безопасна при работающей индексации: `set_payload` не блокирует upsert'ы.
- Пишет батчами по 500 операций в одном запросе.

⚠️ **Порядок назначения — по возрастанию `doc_id`, и это не косметика.** При совпадении кодов
удлиняется код того, кто «пришёл позже», а «позже» здесь задаётся именно сортировкой. Без неё два
прогона на одном корпусе разошлись бы в кодах у той доли документов, что удлинилась.

## 3. Payload-индекс

Команда создаёт его сама и сообщает результат. Проверить:

```bash
curl -s localhost:6333/collections/<docs> | jq '.result.payload_schema|keys'   # ждём short_id
```

⚠️ Индекс **не появится сам** при обычном запуске: `ensure_docs_collection` делает early-return на
существующей коллекции, и индексы создаются только при первом её создании. Без индекса разворот
кода пойдёт сканом — на корпусе в тысячи документов это заметно.

## 4. Карта знаний

```bash
python -m cli.main rebuild-km --config <config.yml>
```

⚠️ **Без этого шага Карта останется на длинных идентификаторах**, и рядом будут жить две формы:
короткие коды в выдаче `search` и длинные в Карте. Именно из такой смеси агент и собирает гибриды
вида «префикс раздела + заголовок» — то, ради чего вся правка. Переиндексации `rebuild-km` не
требует.

## 5. Рестарт отвечающей части

```bash
docker compose restart <pipelines-сервис>
```

Таблица «код ↔ документ» живёт в корпус-снапшот кэше с TTL 300 с, так что старый процесс подхватил
бы коды и сам, но рестарт делает переход мгновенным.

## 6. Проверка

```bash
# доля документов с кодом и уникальность
curl -s -X POST localhost:6333/collections/<docs>/points/scroll \
  -H 'content-type: application/json' \
  -d '{"limit":1000,"with_payload":["id","short_id"]}' \
  | jq '[.result.points[].payload.short_id] | (length), (unique|length)'
```

Оба числа обязаны совпасть с числом документов.

В логе отвечающей части при каждом обращении агента к идентификатору теперь видно, что он передал
и чем это кончилось:

```
[ids] get_doc.doc_id='D7QK2MV' resolved to local:corp:a/b/c/doc.md
[ids] get_doc.doc_id='D7QXMEV' REFUSED: Код D7QXMEV испорчен при переписывании
```

⚠️ Если в логе есть строка `short ids: N from payload, M derived on the fly (run
backfill-short-ids)` — миграция сделана не для всего корпуса. Это рабочее состояние, но разворот
идёт по вычисленной таблице, а не по индексу.

## 7. Откат

Одна строка конфига, он горячий:

```yaml
retrieval:
  features:
    doc_ids_in_results: grouped   # прежнее поведение
```

Поле `short_id` при этом остаётся в базе и никому не мешает. Удалять его не нужно.

## Что делать, если коды «поехали»

Коды выводятся из `doc_id`, а `doc_id` у локальных источников — это ПУТЬ файла. Переименование или
перенос документа меняет `doc_id`, а значит и код: для базы это новый документ, старый уедет в
сироты и будет удалён каскадом. Это не свойство кодов, а обычное поведение индексатора — но помнить
о нём стоит, если ссылки на коды где-то сохраняются вне диалога.
