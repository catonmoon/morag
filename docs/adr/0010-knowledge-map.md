# ADR-0010: Knowledge Map — карта документации

## Статус

Принято (2026-03-31)

## Контекст

После индексации у нас есть дерево документов с doc_summary для каждого узла.
Но при retrieval LLM не знает общую структуру — какие разделы есть, где что искать.
Нужен "оглавление" — иерархическая карта документации для system prompt.

## Решение

### Финальная архитектура

Knowledge Map генерирует **один системный промпт** — структурированный markdown
с описаниями разделов и id для прицельного поиска. Хранится в Qdrant (`knowledge_map`).

### Две стратегии формирования промпта

**`fixed`** — фиксированный лимит на узел:
- Каждый узел получает до `node_max_tokens` (256) на описание
- Итоговый размер = сколько получится
- Описания из LLM-карт узлов (матрёшка снизу вверх)

**`weighted`** — взвешенный бюджет по потомкам:
- Общий бюджет `prompt_budget` (8192) распределяется пропорционально числу потомков
- Корни — без описания (описаны через детей)
- Средние узлы — бюджет пропорционален числу скрытых потомков
- Минимум `node_min_tokens` (256) на узел — защита от обрывов
- Описания генерируются из сырой карты (raw map) потомков — один LLM-вызов на узел

### Алгоритм weighted (финальный)

1. **Структура из Qdrant** — программно строим дерево по `parent_doc_ids`, точная иерархия
2. **Корни из конфига** — `ancestor_ids` определяют корни, сироты отфильтрованы
3. **Плейсхолдеры** — считаем overhead заголовков через TikToken
4. **Бюджет** — `(prompt_budget - overhead) × (потомки + 1) / total_weight`, min = `node_min_tokens`
5. **Для каждого среднего узла**: собираем raw map (doc_summary всех потомков с h-заголовками) → LLM обобщает с `max_tokens=budget`. Один вызов — LLM видит всю картину
6. **Fallback**: если raw map > контекста LLM → матрёшка (пакетное обобщение)
7. **Корни** — только заголовок + id, без описания
8. **Title** — вырезается иерархически (path - parent_path), не split по `/`

### Промпт для LLM

Описательный стиль, без markdown-заголовков в описании (структура программная):
```
Write a descriptive overview of this section:
- Describe what this section covers and what information can be found here
- Mention key topics, tools, processes and roles covered
- Be specific: include names of systems, frameworks, teams where relevant
- Write in flowing prose, not as a list
- Do NOT use markdown headings
```

### Конфигурация

```yaml
indexing:
  knowledge_map:
    enabled: true
    depth: 2                  # уровней в системном промпте
    # max_depth:              # макс. глубина обхода; не задано = до самого дна
    prompt_strategy: weighted # 'fixed' | 'weighted'
    prompt_budget: 8192       # для weighted: общий бюджет системного промпта
    node_max_tokens: 256      # для fixed: лимит на узел
    node_min_tokens: 256      # для weighted: минимальный бюджет на узел
```

### Результаты тестирования

Корпус: 443 документа (Люди + Организация + Образовательные активности), 3 корня.

| Стратегия | Chars | Tok | Обрывы | Описания |
|---|---|---|---|---|
| fixed | 13182 | 5565 | 0 | Полные, без ограничений |
| weighted (финальный) | 15482 | 6321 | 0 | Богатые, пропорциональные |

Weighted: 17 узлов в промпте (14 non-root), 7893 tok available.
Узел "Инструкции" (21 потомков) → развёрнутое описание с конкретными инструментами.
Узел "Мотивация" (0 потомков) → 256 tok min, полное описание.

### Хранение

- Коллекция `knowledge_map` в Qdrant
- Единственная обязательная запись: `doc_id='_system_prompt'`, `map_text=...`
- Для fixed также хранятся промежуточные карты узлов
- Перезаписывается при каждом запуске

### Использование при retrieval

- Inject `_system_prompt` в system prompt при retrieval
- LLM видит структуру → определяет раздел → id для фильтрации поиска
- 6K tok — ~5% от контекстного окна LLM (131K)

## Эволюция решения

1. LLM-обобщение корневых карт → LLM перегруппировывал, терял структуру
2. Программная сборка дерева + LLM-карты узлов → структура точная, но обрывы
3. Raw map (все potомки с h-заголовками) → один LLM-вызов, LLM видит всю картину
4. Weighted бюджет + node_min_tokens → 0 обрывов, пропорциональные описания
