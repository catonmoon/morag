# ADR-0002: Выбор Vision LLM модели для PDF-конвертации

**Статус**: принято
**Дата**: 2026-03-15
**Контекст решения**: выбор оптимальной модели для постраничной конвертации PDF → Markdown

## Контекст

morag конвертирует PDF-документы в Markdown двумя способами:

- **docling**: структурный парсер (docling-serve) + Vision LLM для изображений/формул
- **vision**: постраничный рендеринг в PNG → Vision LLM → Markdown

Vision-режим проще в деплое (не требует docling-serve), но качество зависит от модели.
Проведено [исследование](../../reports/pdf_vision_vs_docling.md) на 13 итерациях (v0–v8b)
с тестовым документом (38 страниц, документ с таблицами, формулами, диаграммами, русский текст).

### Протестированные модели

| Модель | Размер | Результат |
|---|---|---|
| qwen3-vl-30b (8bit) | 30B | Garbled-слова от repetition_penalty, двойные запятые в числах, отсутствие Таблицы А2 |
| qwen3-vl-32b-thinking (8bit) | 32B | Таймауты, 502 ошибки при concurrency≥4, ~7 мин/страница |
| **qwen3.5-9b (8bit)** | **9B** | **Чистый текст, корректные таблицы, 2:01 на 38 страниц (c=16)** |

### Ключевые находки

1. **Thinking-модели не подходят для OCR**: задача перцептивная, думание тратит токены и время.
   `max_tokens` включает thinking-токены — бюджет на полезный контент сокращается.

2. **Нативная мультимодальность > отдельный VL-адаптер**: Qwen3.5 использует early fusion
   (мультимодальные токены в pre-training), Qwen3-VL — отдельный Vision Encoder.
   Результат: 9B модель даёт качество лучше 30B.

3. **repetition_penalty работает чище на Qwen3.5**: garbled-слова (`подходоводов`,
   `применимодности`) и двойные запятые (`0,0,0023`) — проблема Qwen3-VL, не Qwen3.5.

4. **concurrency масштабируется**: 9B модель позволяет c=16–32 без таймаутов. 30B модель
   упиралась в c=8, 32B-thinking — в c=4.

## Решение

### Рекомендуемая модель: `qwen3.5:9b` через Ollama

Для обоих LLM-клиентов (текстовый `llm` и мультимодальный `llm_vision`):

```yaml
llm:
  base_url: http://localhost:11434/v1
  model: qwen3.5:9b
  api_key: ollama

llm_vision:
  base_url: http://localhost:11434/v1
  model: qwen3.5:9b
  api_key: ollama
  enable_thinking: false
```

**Обоснование единой модели:**
- Qwen3.5 нативно мультимодальна — одна модель для текста и изображений
- Одна модель в памяти GPU вместо двух → экономия VRAM
- Упрощает деплой и обновление
- На текстовых задачах (чанкинг, контекст, саммари) Qwen3.5-9B не уступает Qwen3-coder
  благодаря MoE-архитектуре

### Параметры Vision-режима

```yaml
pdf:
  mode: vision
  page_max_tokens: 8192
  concurrency: 16              # оптимальный баланс скорости и нагрузки
  temperature: 0.1
  repetition_penalty: 1.2
  context_tail_lines: 0
  postprocessing:
    strip_code_fences: true
    dedup:
      enabled: true
      threshold: 0.7
      window: 5
      min_phrase_len: 20
```

### Параметр `enable_thinking`

Добавлен в `LLMConfig` и `GenerationParams` для управления thinking-режимом:
- `enable_thinking: false` → `extra_body={"chat_template_kwargs": {"enable_thinking": false}}`
- `enable_thinking: null` (или не задан) → поведение модели по умолчанию
- Страховка: `_strip_thinking()` в `LLMClient` удаляет `<think>` теги из ответов

## Последствия

### Положительные

- **Качество**: чистый русский текст без garbling, корректные таблицы и формулы
- **Скорость**: 38 страниц за 2:01 (c=16) — x2.5 быстрее qwen3-vl-30b
- **Ресурсы**: 9B vs 30B → ~3x меньше VRAM, одна модель вместо двух
- **Деплой**: `ollama pull qwen3.5:9b` — единственная зависимость для LLM
- **Стабильность**: 0 таймаутов и ретраев при c=16

### Отрицательные

- Temperature 0.1 (необходима для сброса кэша omlx) → результаты слегка варьируются между прогонами
- Единичные обрывы предложений на границах страниц (~2–3 на 38 стр) — фундаментальное ограничение постраничного подхода
- Docling по-прежнему стабильнее для edge cases (детерминированный парсинг)

### Риски

- Qwen3.5 — новая модель (март 2026), может содержать неизвестные баги
- Ollama может отставать с поддержкой новых моделей — проверять совместимость
- При переходе на другой inference-сервер (vLLM, omlx) параметр `enable_thinking` пробрасывается через `chat_template_kwargs` — проверить совместимость

## Альтернативы, которые были отвергнуты

### 1. qwen3-vl-30b (текущий)

Garbled-слова, двойные запятые в числах, потеря Таблицы А2. Медленнее при бо́льшем размере.

### 2. qwen3-vl-32b-thinking

Слишком медленная для batch-задач (~7 мин/стр). Thinking тратит бюджет `max_tokens`
на рассуждения, не нужные для OCR. Сервер не держит concurrency>4.

### 3. Специализированные OCR-модели (DeepSeek-OCR, dots.ocr)

1.7–3B параметров, секунды на страницу. Потенциально лучше для чистого OCR,
но не проверены на русском тексте в нашем pipeline. Рассмотреть как следующий шаг.

### 4. Две разные модели (текст + vision)

Сложнее деплой, больше VRAM, необходимость синхронизировать обновления.
Qwen3.5-9B покрывает оба use case.
