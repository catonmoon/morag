# ADR-0031: Конвейер распознавания по узлам (было: «граф состояний») — заменил линейный

## Статус

**Принят, 2026-09-29.** Конвейер по узлам (`services/asr-adaptor/conveyor/`) заменил линейный
`pipeline.run_pipeline`: одна реализация на все профили. Выход прежнего конвейера на заглушках
заморожен в `tests/asr_adaptor/golden/` перед удалением, и новый сверяется с ним на каждом прогоне
тестов. LLM-оркестратор по месту снят. Решения по тексту модель принимает только в узле
**редактора** (`ASR_EDITOR`, поле формы `editor=`), выключенного по умолчанию.

Словарь поправлен по вопросу владельца корпуса: «если граф линейный, чем он отличается от старого
конвейера?» — по управлению ничем: переходы только вперёд, условный узел пропускается по флагу.
Поэтому «граф» в названиях снят. Отличия инженерные — узел вместо функции на пятьсот строк,
продолжение с упавшего узла, журнал каждого решения, место для редактора.

История: 2026-09-28 — эксперимент рядом с линейным (`ASR_PIPELINE=legacy|graph`, ветка
`asr-graph`), замер трёх рук ниже; 2026-09-29 — редактор, замена линейного, снятие оркестратора.

## Контекст

ADR-0030 закрыл вопрос «испортится ли распознавание от агентского подхода» и дал правила: слушать
окно целиком, второе ухо — модель другой школы, голосование под вето свидетеля, **модель предлагает,
подтверждают звук, канон и экран**. Но сам конвейер остался одной функцией `run_pipeline` на пятьсот
строк с замыканиями:

- стадию нельзя вызвать отдельно, а упавшую на двадцатой минуте запись — продолжить с места;
- инструмент (ухо, читатель, правка) нельзя подменить, а решение по месту — отдать другой политике;
- промпты стадий — константы публичного движка: домен, которому нужен свой текст, мог только
  форкнуть код;
- «агентность» жила в прототипе для замеров, не в движке.

Решение владельца корпуса: перейти к конвейеру по узлам — но как к эксперименту, с возвратом одним
переключателем, настройкой промптов и сравнением трёх рук по качеству и скорости: линейный
конвейер, по узлам с политикой-правилами, по узлам с LLM-оркестратором, который сам выбирает инструменты.

## Решение

### Форма

```
conveyor/state.py    State: что узел читает и пишет; чекпойнт в JSON (без центроидов голосов)
conveyor/deps.py     позднее связывание к pipeline.*: помощники, семафоры, билеты реестра
conveyor/events.py   лента событий (форма прежняя: её читает окно загрузки записи)
conveyor/nodes.py    узел на стадию; NODES = [(имя, fn, условие по конфигу)]
conveyor/tools.py    Tool / Registry: схема аргументов, журнал каждого вызова, учёт цены
conveyor/loop.py     Place + decide_place: цикл по месту с бюджетом шагов
conveyor/policy.py   RulePolicy (оркестратор LLMPolicy снят 29.09)
conveyor/places.py   инструменты места: кусок арбитража, реплика финал-раунда
conveyor/editor.py   редактор расшифровки: страницы, listen / lookup / propose, вето по роду правки
conveyor/run.py      run_conveyor — результат прежней формы + ключ conveyor
prompts.py        реестр промптов стадий, ASR_PROMPTS=<toml>, --dump
```

**Места** — там, где конвейер принимает решение: кусок пасса-2 в арбитраже (читатель → второе ухо →
правила → третий голос по требованию) и реплика в финал-раунде (вспомнить сущности → предложить
замены → звук по отвергнутым заменам известных слов). Остальные стадии — узлы без выбора.

### Правила, купленные живым прогоном

Первая версия открывала модели все инструменты, включая применение. На короткой записи оркестратор:
сам писал текст через `apply_fix` («Не подделка?» → «Не-е-е. Подделка?»); своим «skip» отменял
решения правил — взял одну замену из пятнадцати, то есть судил против свидетелей; звал применение
дважды; у реплики «skip» выбрасывал правки. И терял места целиком: обрезанные аргументы вызова,
возвращённые в историю переписки, шлюз отвергал с 400 на всю переписку. Отсюда:

1. **Применение — внутренний инструмент** (`Tool.internal`): его нет в схемах модели, вызов из цикла
   отвергается. Решения правил применяет узел, если второе ухо слушали, — независимо от слова политики.
2. **`apply_fix` — только по звуку:** замена обязана быть предложена правкой, отвергнута сторожем
   известных слов и подтверждена `sound_prefers = now`; иначе отказ в коде, не в промпте.
3. **`finish` заканчивает место, но не судит текст.**
4. **Инструменты без влияния на исход — не в наборе модели** (сверка с каноном и частотник: правила
   делают это сами, у модели это чистая цена).
5. **Битые аргументы в историю не возвращаются** — модели сообщается ошибка обычным сообщением.

⇒ У LLM-оркестратора остаётся ровно то, что ему можно доверить по ADR-0030: **какие проверки стоят
своей цены на этом месте** — звать ли второе ухо, звать ли третий голос, каким окном.

### Эквивалентность и возврат

- Пока жили оба, узлы брали помощники `pipeline.py` атрибутом модуля в момент вызова, и одни
  заглушки гоняли обе реализации; золотой тест держал равными результат, ленту событий и вызовы
  аудио-бэкенда на шести наборах флагов. При замене выход линейного заморожен
  (`tests/asr_adaptor/golden/`), тест (`test_conveyor_equivalence.py`) сверяет с ним; обновить
  снимок — только осознанно, `--update-golden`, с объяснением в коммите.
- Чекпойнт после каждого узла (`ASR_CHECKPOINTS`), 0600, центроиды не пишутся;
  `run_conveyor(resume=)` продолжает с первого непройденного узла.

### Промпты файлом

Стадии читают константы промптов в момент вызова, поэтому переопределение — подмена атрибута при
старте, без правки стадий. Ключ — стабильное имя (`final.correct.system`), не имя константы.
Неизвестное имя и потерянный слот (`@CORPUS@` и др.) — отказ старта. Тест интроспекцией держит
каждую константу `*_SYS` стадий зарегистрированной. Доменные тексты живут у домена.

## До / после (28.09, три руки)

Три руки на одном стенде: пять записей с выверенными окнами (≈ 88 минут звука, ≈ 300 слов эталона),
по два прогона, руки по кругу; выбор руки — полем формы.

| рука | WER окон п1 / п2 | CER | имена верно / упущено | всего, с | вызовов LLM | звука слушали, с |
|---|---:|---:|---:|---:|---:|---:|
| линейный конвейер | 9.9 / 10.2 | 6.0 | 5.5 / 1.5 | 1433 | ≈ 530 | — |
| по узлам, правила | 10.2 / 9.1 | 6.7 | 6 / 1 | 1405 | 530 | 4 780 |
| по узлам, LLM-оркестратор | 8.0 / 8.0 | 5.7 | 6 / 1 | 1646 | 530 + 1 725 | 6 010 |

- **По узлам с правилами — равен линейному конвейеру** — и по золотому тесту на заглушках, и живьём (в
  шуме прогона по качеству, 1405 против 1433 с по времени).
- **Выигрыш LLM-оркестратора на окнах не доказан:** разница — около шести слов из трёхсот, шум
  одного окна между прогонами одной руки — до семи пунктов. Имена равны.
- **Цена оркестратора доказана:** +15 % времени, +1 700 вызовов модели, +25 % прослушанного звука.

Рекомендация 28.09: по узлам с правилами — кандидат в основной конвейер (ничего не стоит, даёт промпты файлом,
журнал вызовов, возобновление с узла); LLM-оркестратор — выключенная ручка, пока эталон не вырастет
настолько, чтобы различать эффект меньше шума.

## Редактор вместо оркестратора (29.09)

Оркестратор решал «что звать дальше» на каждом куске в 28 с — около двадцати вызовов модели на минуту
записи. Редактор — агент как человек, который переслушивает запись: системный промпт описывает роль
и домен, у него инструменты (`listen` — окно 20–30 с чистым ухом или второй моделью, `lookup` —
известные написания записи, `propose` — правка), он читает страницу черновика в ~4 минуты с голосами
и временем и за один ответ заказывает несколько инструментов. Бюджет — около одного вызова модели на
минуту записи. Перенос на другой домен — системный промпт и набор инструментов, код не меняется.

Вето — в коде, и какой свидетель нужен, решает код по РОДУ правки, а не модель (четыре живых круга
на одной записи, каждый чинил свою дыру):
- латиница в новом слове — канон, буква в букву среди известных написаний записи;
- слово звучит иначе — звук: в переслушанном окне слышно новое слово; другая форма того же слова —
  только дословно (похожесть звучания грамматику не доказывает);
- то же слово латиницей иначе — хватает канона;
- вето финал-раунда (перевод, выдуманное имя, изъятие, число, известное слово) судит только
  меняемые слова, а место задаёт вся фраза: лимит «три слова» отвергал верные правки за слова-адрес.
Алфавит сам по себе — не ошибка: термин кириллицей по звуку так же верен, как латиницей; редактор
не тратит на это правки.

Замер — на эталонах ЦЕЛЫХ записей, проверенных человеком (не окнах по 30 с); итог двух кругов — в
документации корпуса. Первый круг: редактор против той же сборки с финал-раундом — в пределах шума
одного прогона по WER, больше мест, которые правил человек, +20 % времени, ~1.2 вызова модели на
минуту записи.

## Последствия

- Одна реализация: правка стадии делается в одном месте; поведение на заглушках держит снимок.
- Артефакт несёт `x_enriched.conveyor`: пройденные узлы, журнал инструментов и решений редактора,
  счётчики. Прежнего ключа `graph` больше нет.
- Переменные: `ASR_PIPELINE`, `ASR_GRAPH_POLICY` сняты; `ASR_GRAPH_CHECKPOINTS` → `ASR_CHECKPOINTS`,
  `ASR_GRAPH_PLACE_STEPS` → `ASR_PLACE_STEPS`, `ASR_GRAPH_EVENTS` → `ASR_NODE_EVENTS` (событие
  `conveyor.node`); новый `ASR_EDITOR`. Клиент: `EDITOR_RUN=1|0` вместо `PIPELINE=`.
- Подкаст и любой профиль без `ASR_EDITOR` получают прежнее поведение (снимок тот же).
