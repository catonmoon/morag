# ADR-0018: Кросс-эпизодный реестр голосов на верификационном эмбеддере

## Статус

Принято (2026-06), реализовано в `services/asr-adaptor` (`registry.py`, CAM++-бэкенд) и обкатано
на 53 выпусках (2 ведущих + 14 гостей). Реестр — локальный JSON с биометрическими центроидами,
**в git и публичные артефакты не выкладывается**.

## Контекст

Диаризация отвечает «в этой записи N голосов, вот их реплики», но не «кто эти люди». Для подкаста
нужно **узнавать людей между выпусками**: ведущие в каждом выпуске, гости возвращаются.

**Измеренный парадокс:** эмбеддер, которым пользуется диаризация (wespeaker), на кросс-эпизодном
узнавании давал голосу ведущего сходство с самим собой **0.55**, а с чужим голосом — **0.75**:
путал хуже монетки. Причина — разные задачи обучения: кластеризация голосов *внутри одной записи*
(разделить говорящих здесь и сейчас) и верификация личности *между записями* («тот же ли это
человек?») — разные профессии. Верификационный эмбеддер **CAM++** (3D-Speaker) на тех же данных:
свой 0.95, чужой 0.33.

Второе измерение: LLM-реконсиляция по тексту хорошо чинит *структуру* (сколько реальных людей,
какие кластеры слить), но ненадёжна в *личностях* (путала спикеров местами).

## Решение

Разделение труда «личность ≠ структура»:

- **Реестр голосов (CAM++) = личность.** Глобальный кросс-эпизодный `Speaker_N`: центроид кластера
  сравнивается с реестром (порог 0.55); знакомый голос → тот же ID, незнакомый → новый. Сам чинит
  over-split диаризации (обе половины пересплитенного ведущего матчатся в один person_id).
- **LLM = структура и имена из текста.** Авто-наминг: истина — интро выпуска (ведущие представляют
  гостя) → LLM мапит `Speaker_N` → имя; реестр — fallback. Конфликт (интро называет другого,
  а реестрового имени в интро не звучит) → верим интро, ставим флаг (ловит ложные voice-матчи
  на пороге).
- Прогон корпуса — последовательный (детерминизм нумерации); хранилище — локальный JSON рядом
  с аудио-машиной (не Qdrant: матч голоса не должен зависеть от удалённого RAG-стека).

## Последствия

- Ведущие узнаются в любом выпуске без разметки; новый гость именуется из интро один раз и дальше
  узнаётся по голосу (проверено: гость, появившийся в выпуске 2-24, вошёл в реестр автоматически).
- Метки спикеров в транскрипте приходят из реестра, а не из текста — ASR-гарблы имён в репликах
  не ломают атрибуцию.
- Реестр — биометрические данные реальных людей: живёт только локально; воспроизводимость для
  чужого корпуса = пустой реестр + наминг из интро, сидировать вручную не обязательно.
- Ограничение: однофамильцы и ложные матчи на пороге требуют флагов/ручного разбора
  (см. TODO «само-улучшающийся наминг» в доке asr-adaptor).
