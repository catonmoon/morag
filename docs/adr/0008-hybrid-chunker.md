gjcvjnh# ADR-0008: HybridChunker как режим чанкинга по умолчанию

## Статус

Принято (2026-03-28)

## Контекст

SemanticChunker (режим `semantic`) использует embedding-based boundary detection:
жадный L→R алгоритм, батчевый embed пар кандидатов (left+right), выбор границы
с максимальным cosine distance. Два основных недостатка:

1. **Потеря markdown-структуры**: SemanticChunker объединяет semantic units через
   `' '.join()`, уничтожая переносы строк, списки, подпункты. На юридических
   документах 10+ из 13 чанков — однострочные.

2. **Производительность**: на каждую границу — батч embed-вызовов. На реальном
   FRIDA через HTTP: 85.7s на документ 1716 токенов, 667s на 21K токенов.
   6 документов (~42KB) — 17 минут.

Для монотонных текстов (юридические документы, нормативные акты) embedding distance
плохо находит семантические границы — режет хаотично, создаёт микрочанки (56, 58, 64 tok).

## Решение

Новый режим `hybrid` (HybridChunker) — структурный чанкер на CommonMark AST.

### Алгоритм

**Stage 1: _parse_blocks** — разбор документа на типизированные блоки:
- `_split_by_headers()` → секции по заголовкам
- `_top_level_blocks()` → блоки через CommonMark AST
- Классификация: heading, paragraph, table, fence, diagram, list

**Stage 2: _greedy_fill** — жадное наполнение чанков:
- Набираем блоки пока ≤ max_tokens
- **Магнитные заголовки**: при закрытии чанка, если последний блок — heading,
  выталкиваем его в следующий чанк (заголовок всегда в начале, не в конце)
- Oversized блок (> max_tokens) → обработка по типу:
  - Текст/список → split_sentences() → жадная упаковка предложений
  - Таблица → TableRowSplitter (строки с дублированием шапки)
  - Code fence → по строкам с re-wrap fence markers
  - Диаграмма → as-is или LLM (configurable)
  - Oversized предложение/строка → configurable стратегия (fixed/embed/llm)

**Stage 3: _post_merge** — склейка мелких чанков:
- Чанк < min_tokens → попробовать склеить с предыдущим или следующим
- Исключения: единственный чанк документа, последний чанк

### Конфигурация

```yaml
indexing:
  chunker:
    mode: hybrid                  # новый default
    min_tokens: 50
    max_tokens: 250
    oversized_strategy: fixed     # fixed | embed | llm
```

`skip_presplit = True` — HybridChunker получает полный текст документа
и обрабатывает всё самостоятельно (как SemanticChunker).

### Качественные

- **Markdown-структура**: hybrid сохраняет переносы, списки, подпункты.
  Semantic уничтожает через `' '.join()`.
- **Логическая группировка**: hybrid группирует по структуре документа
  (статьи, секции). Semantic режет по скачкам embedding distance — хаотично
  на монотонных текстах.
- **Магнитные заголовки**: заголовок всегда в начале чанка, не болтается в конце.
- **Детерминистичность**: hybrid не зависит от embedder, результат воспроизводим.

## Обратная совместимость

- Default в `ChunkerConfig` изменён с `semantic` на `hybrid`
- Существующие конфиги с явным `mode: semantic` продолжают работать
- При переходе на `hybrid` требуется полная переиндексация (`--reset`),
  т.к. границы чанков изменятся

## Альтернативы

1. **Исправить `' '.join()` в SemanticChunker** — решит потерю markdown,
   но не решит проблему производительности и хаотичных границ на монотонных текстах.

2. **Оставить semantic по умолчанию** — отвергнуто. Hybrid объективно лучше
   по всем метрикам для структурированных документов. Semantic остаётся
   как опция для edge cases (сплошной текст без структуры).
