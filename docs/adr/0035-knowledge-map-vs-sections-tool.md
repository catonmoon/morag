# ADR-0035: Карта знаний в промпте не окупается; тул описаний разделов — эксперимент

## Статус

**Принято** (2026-10-28). Карта знаний выключена по умолчанию (`indexing.knowledge_map.enabled: false`
в `conf/config.yml`). Тул `sections` есть в main как опциональный: по умолчанию его нет, включается
записью в `retrieval.tools`.

## Контекст

Карта знаний (ADR-0010) уходит в системный промпт целиком в каждом запросе. На проде размер доходил
до 14 тыс. токенов по tiktoken. Её польза для ответов никогда не измерялась: в ADR-0010 замерен только
размер.

Гипотеза владельца: агенту нужна не Карта целиком, а инструмент, который отдаёт описание раздела
по запросу, только когда это нужно.

## Эксперимент

Корпус Confluence: ≈9,3 тыс. документов, 11 корневых разделов. 396 вопросов с эталонными ответами
от людей. Агент и реранкер одинаковые во всех плечах, `find_section` обязателен.

| Плечо | Карта в промпте | Тул `sections` |
|---|---|---|
| km | да | нет |
| tool | нет | да, со строкой-подсказкой в методике |
| tool_silent | нет | да, без подсказки |
| none | нет | нет |
| tool_live (100 вопросов) | нет | да, плюс описание любого раздела из docs |

- Все плечи читали одну сборку Карты. Тул отдаёт те же тексты узлов, что напечатаны в Карте.
- Системные промпты сверены `diff`: tool_silent и none совпадают байт в байт.
- Судья — слепой LLM, ответы в случайном порядке, якорные вопросы в каждом батче.

## Замеры

| | средний балл (0–10) | вызовов инструментов | медиана, с |
|---|---:|---:|---:|
| km | 8,42 | 3,64 | 38 |
| tool | 8,47 | 3,40 | 34 |
| tool_silent | 8,45 | 3,34 | 34 |
| none | 8,56 | 3,26 | 34 |

- Парные разности: tool − km +0,05 [−0,16; +0,26], none − km +0,14 [−0,08; +0,36]. Все интервалы
  включают ноль.
- Подвыборка: tool_live − km +0,28 [−0,20; +0,75], tool_live − none 0,00.
- Размер Карты в эксперименте: 5 331 токен по tiktoken и 4 420 по Qwen. Вытеснения чанков бюджетом
  контекста (`ctx-budget`) не было ни в одном плече. Цена Карты — только токены промпта и ~4 с.
- С Картой агент делает больше вызовов (`get_doc` +45 %), на качестве это не отражается.
- Тул `sections` агент почти не зовёт: 8 раз на 396 вопросов с подсказкой, 2 раза без неё,
  6 раз на 100 вопросов в режиме tool_live. Все 7 запросов узла по коду были кодами из выдачи
  `find_section`, которых нет среди узлов Карты.
- Шум: на 11 % вопросов плечи расходятся на 6 баллов и больше при одинаковых данных. Значимы только
  агрегаты.

## Решение

1. Для иерархических корпусов с обязательным `find_section` Карту выключать. Навигацию уже закрывает
   `find_section`: поиск по уровню документов с агрегацией по родителям.
2. Код Карты не удаляем. Флаг `enabled` выключает её и в ответах, и при индексации.
3. Тул `sections` остаётся опциональным и по умолчанию выключен: как замена Карты он ничего
   не добавляет, но нужен для следующих замеров (плоский корпус, `find_section` OPTIONAL).
4. Вместе с тулом исправлена отдельная ошибка: оверрайд секции `tool_methodology` в конфиге молча
   отбрасывал подсказки опциональных тулов.

## Конфиг

```yaml
indexing:
  knowledge_map:
    enabled: false        # true — Карта снова в промпте и строится при индексации
retrieval:
  tools:
    - type: sections      # описания разделов по запросу; читает узлы Карты
      hint: true          # строка в методике промпта «начни с sections()»
      live: false         # true — описывать и разделы, которых нет в Карте (из docs-коллекции)
```

Тулу нужны узлы Карты: они пишутся при её сборке. С выключенной Картой тул работает только
в режиме `live`.

## Почему не иначе

- **Оставить Карту «на всякий случай».** Измеримой пользы нет, а цена есть на каждом запросе.
- **Заменить Карту тулом.** Агент его не вызывает. Подсказка в промпте поднимает частоту вызовов
  в 4 раза, но от 2 до 8 на 396 вопросов, и качество не меняется.

## Границы и риски

- Один корпус и одна модель агента. Для плоских корпусов (`flat_topics`) и при необязательном
  `find_section` вывод не проверен: там Карта может быть единственной навигацией.
- Интервал ±0,2 балла не исключает эффекта Карты меньше 0,3 балла.
- Судья — LLM: повторная оценка совпала с первой в 64 % случаев, среднее расхождение 0,42 балла.
